# Forte Vision: интерфейс участника 4

Интерфейс по плану `04_frontend_demo.md`: загрузка MOV в общий API, ожидание задания, просмотр вердикта, всех событий, кадров, временных отметок и нормативных оснований. Оформление основано на бесплатном Slate Admin Console v1.0.4 из [Skillry](https://skillry.dev/skills/bs-slate-admin-console). Оригинальный логотип взят из шапки [официального сайта Forte](https://forte.kz/), цвет и геометрия сохранены. Прототип Datathon не является официальным продуктом банка.

## Запуск

Из папки `frontend`:

```sh
python -m http.server 4173 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:4173`. Это только локальный предпросмотр статических файлов; отдельного сервера анализа в frontend нет. Сборка и установка npm-пакетов не нужны. Проверка синтаксиса: `npm run check` или `node --check app.js`.

В общей конфигурации участник №3 раздаёт эту папку общим сервером. Для открытия на одном адресе с API поле «Адрес сервера» оставляют пустым. Если адреса различаются, задают полный адрес сервера команды, а backend разрешает CORS для конкретного origin интерфейса, методов GET/POST и заголовка `X-API-Key`. В production используют HTTPS.

## Настройки и API

1. Открыть «Настройки», указать адрес общего API при необходимости.
2. Ввести ключ доступа. Ключ живёт только в памяти страницы, не попадает в localStorage, URL или репозиторий. После перезагрузки его вводят снова.
3. Нажать «Проверить готовность».
4. Выбрать непустой `.mov` и нажать «Начать анализ».

| Операция | Контракт |
| --- | --- |
| Готовность | `GET /readyz`; HTTP 2xx и `ready: true` либо `status: ready/ok/healthy`. Явное `ready: false` имеет приоритет. Если backend выберет другую схему, согласовать `checkReady()` в `app.js`. `/healthz` не используется. |
| Загрузка | `POST /api/v1/analyze`, `X-API-Key`, `FormData` с одним полем `file`. Content-Type вручную не задаётся. Ответ HTTP 202: `{job_id, status: "processing", mode}`. |
| Статус | `GET /api/v1/jobs/{job_id}`, `X-API-Key`, последовательный опрос раз в 1,6 секунды. Одновременных циклов нет. |
| Результат | `status: done`, `verdict: violation/no_violation`, `violations: []`. Все поля событий и кадров берутся из ответа сервера. |
| Сбой | `status: failed`, `error.message`. Вердикт не отображается. |

Клиент поддерживает дополнительные поля `mode`, `analysis`, `violations[].rule` (`id`, `document`, `section`, `source_url`). `analysis` показывается без выдуманных показателей. Для источников допускаются только HTTP/HTTPS без логина и пароля; ссылки открываются отдельно с `noopener noreferrer`. Модельный текст экранируется и не исполняется как HTML.

События требуют `type`, неотрицательный `timecode_sec`, `description`, 1–3 `evidence_frames` с неотрицательным `timestamp_sec` и JPEG base64 без data:-префикса. Несогласованный вердикт или повреждённый ответ не превращается в «нарушений нет». Время события и время кадра показаны отдельно. Ссылка на отсутствующий нормативный источник не придумывается.

Максимальный размер файла определяет общий сервер: браузер показывает имя и размер, проверяет расширение/пустоту, а HTTP 413 объясняет превышение лимита. При согласовании конкретного лимита участник №3 может передать его интерфейсу; произвольный предел в браузер не зашит.

## Ожидание и восстановление

- Во время отправки/обработки повторный запуск блокируется.
- POST автоматически не повторяется ни при каких сетевых ошибках.
- После получения `job_id` он остаётся на экране при потере связи. «Запросить статус» выполняет GET для прежнего задания на том же сервере, без повторной загрузки.
- После 5 минут ожидания автоматический опрос прекращается. Можно вручную запросить состояние существующей задачи.
- «Прекратить ожидание» останавливает запросы браузера. API отмены задания в контракте нет; UI не утверждает, что серверная обработка отменена.
- Если ответ POST потерян, сервер мог принять файл, но `job_id` неизвестен. UI явно сообщает об этом, не загружает файл повторно и рекомендует уточнить состояние у команды.
- «Новая проверка» очищает прошлый результат. Поздние ответы старой операции игнорируются. Перезагрузка страницы удаляет ключ и состояние задания: ID при необходимости нужно сохранить отдельно.

## Демо и ограничения

«Открыть демо» и сценарии в настройках работают без API. Они используют локально нарисованные схемы и явно помечены DEMO. Выбранное пользователем видео не анализируется в демо и не получает синтетический результат. Ответы API с `mode: demo/test` получают заметное предупреждение. Если `mode` отсутствует/неизвестен, UI не подтверждает, что результат реальный.

MOV может не воспроизводиться в конкретном браузере. Это не мешает передаче файла и просмотру кадров API. Плеер и переход ко времени являются дополнительными возможностями. Вычисление анализа выполняет сервер команды; браузер не вызывает облачные AI API. Данные, кадры, видео и ключи не сохраняются в репозитории.

## Передача участнику №3

Сохраняйте `frontend/index.html`, `frontend/app.js`, `frontend/style.css`, `frontend/assets/` и `frontend/fonts/` вместе. Обязательных CDN нет. Backend не изменён этой поставкой. Прежний черновой контракт `window.ForteUI` не используется: сетевой адаптер уже включён в `app.js` согласно новому плану.

Перед сдачей нужны настоящий адрес API и ключ, согласованная схема `/readyz`, проверенная модель и каталог. После подключения повторить сценарии из `QA.md` на реальных ответах, сверить карточки с JSON и проверить публичный адрес с другого устройства. Пока сервер команды не готов, реальный сквозной анализ и публичное развёртывание не подтверждены.

Сценарий выступления: `DEMO.md`. Проверки: `QA.md`. Лицензии шрифтов находятся в `fonts/`; источник логотипа в `assets/README.md`.
