# Проверки интерфейса

Статус передачи: frontend доступен для подключения backend. Настоящий сервер команды ещё не готов. Реальный сквозной анализ и работа через публичный адрес пока не проверены.

Выполнено:

- `node --check frontend/app.js`: синтаксис JavaScript корректен.
- Пять разделов посещены дважды на ширинах 390, 768, 1024 и 1440 px: один видимый заголовок H1, горизонтального переполнения страницы нет.
- Проверены светлый/тёмный режимы и оба цветовых акцента, поиск раздела через Ctrl+K.
- Мобильное меню закрывается при выборе раздела, включая текущий, и переводит фокус на заголовок.
- Исходники используют локальные CSS, JavaScript, логотип и шрифты. Ключ не зашит в код.

В настоящем браузере пройдены ещё **33 проверки на синтетических ответах API**:

- Отдельный DEMO и режим TEST от API заметно помечены; REAL не помечается как демо.
- Оба вердикта, несколько событий, переключение кадров, раздельные отметки события/кадра и увеличение кадра работают.
- Модальное окно возвращает фокус на кнопку кадра. Экран результата помещается на телефоне.
- Неправильное расширение и пустой файл отвергаются до отправки.
- Готовность проверяется через `/readyz`; явное `ready: false` не трактуется как готовность.
- Повторный клик создаёт только один POST с одним multipart-полем `file`; ключ идёт в `X-API-Key` и не сохраняется в localStorage.
- Текст модели показывается буквально, HTML/скрипты не исполняются; `javascript:` не становится ссылкой. Корректная HTTP(S)-ссылка отображается.
- Сведения `analysis` показываются без изменения значений.
- При потере сети ID сохраняется, повторный запрос выполняет только GET.
- `failed`, повреждённый результат и ответ с другим ID не показывают ложный вердикт.
- HTTP 401, 404, 413, 415, 422, 429, 503 отображаются как ошибки.
- Поздний ответ остановленного задания не подменяет новую проверку.
- Необработанных ошибок JavaScript в сценарии нет. В DevTools ожидаемо появляются сообщения о намеренно смоделированных ошибках HTTP/сети.

Это проверка клиента с перехватом запросов Playwright, а не доказательство работы модели. В проверке использовано 14 синтетических POST и 8 GET; настоящие видео не отправлялись.

Дополнительно пройдены 6 проверок: ожидание без выдуманного процента; несколько последовательных `processing` → `done` без параллельных GET; повторный статус для серверного задания с `mode: demo`; сохранение пометки DEMO после повтора; навигация и синтетическое демо автономного HTML внутри `iframe sandbox="allow-scripts"`.

Перед сдачей совместно с участниками №1–3:

1. Согласовать ответ `/readyz`, адрес API, CORS, ключ и ограничения файлов.
2. Выполнить настоящий POST MOV → GET статуса → `done` в режиме `real`.
3. Сверить `job_id`, вердикт, каждый таймкод, JPEG и нормативную ссылку с JSON этого же задания.
4. Проверить видео без событий, одно событие, несколько событий и `failed`.
5. Проверить неверный ключ, 413/415/422/429/503 и потерю сети после получения ID.
6. Убедиться, что «Запросить статус» выполняет только GET и не отправляет MOV повторно.
7. Открыть публичный сайт на другом устройстве и провести сценарий из `DEMO.md`.

Реальные банковские видео и кадры не использовались в браузерных скриншотах и не включены в Git. Для проверок UI используются только синтетические схемы и тестовый файл, не содержащий видеоданных.
